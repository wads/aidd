# 出力フォーマット（Issue コメント）

確定版は以下の形式で GitHub Issueへコメントする。Issue本文は書き換えない。

```md
## 確定版 受入れ条件・品質条件（P2 要求整理）

### 受入れ条件
- AC-1 🔵 [integration] {条件または操作} のとき、{期待結果} になる（出典: Issue本文 受入れ条件 1）
- AC-2 🔵 [E2E] {条件} のとき、{期待結果} になる（出典: 2026-06-12 PdM 回答。本文にない新規）

### 品質条件
- QC-1 🔵 [CI] {測定可能な基準}（例: 検索 API の p95 応答時間が現状から悪化しない）
- QC-2 🔵 [手動] {基準と確認方法}
- 他は対象外（性能・セキュリティ: 影響なしを確認済み）

### 備考
- {対象外にした項目とその理由}

### AI の見解
- 推奨: {確定内容の要点と理由}
- 棄却した代替案: {検討して採らなかった条件・範囲と理由}
- 懸念: {残る懸念。無ければ「なし（理由）」}

### 確認記録（人間の回答の転記）
- ① {YYYY-MM-DD} {問い} → {人間の回答}（{反映先: AC-n / QC-n / 対象外}）
- ② …
```

ルール:

- ID は欠番を作らない。後から追加する場合は末尾に追記し、変更は新しいコメント（Delta）で表す
- マーカーは確定時点で全項目 🔵 であること（🟡・🔴 が残る場合は確定しない）
- 出典は人間が検証できる粒度で書く（「Issue本文 受入れ条件 {番号}」「確認記録 ①」「既存仕様 {リンク}」）
- **チャットで得た人間の回答は「確認記録」節に日付つきで転記し、AC/QC の出典はその番号を指す**。チャットは Issue から辿れないため、「{日付} の回答」とだけ書いた出典は独立レビューから追跡不能になる（2026-09-03 の P2 ゲートで Critical になった実例）。撤回・訂正した回答も消さず、取り下げた旨を同じ番号に追記する
- **Issue 本文の受入れ条件との対応を追跡可能にする**: 本文由来の AC は本文条件の番号を出典に含め、本文にない AC（具体化・分割・エッジケース追加）は「本文にない新規」とその根拠を明記する。本文の全条件がいずれかの AC にマップされていること（対象外にした条件は備考で申告する）
- テストレベル `[unit|integration|E2E]` は AC に、検証手段タグ `[CI|テスト|手動]` は QC に付ける
