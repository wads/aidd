# Retrospective Workflow

1. 対象フェーズやタスクを確認する
2. Keep / Problem / Try で整理する
3. 特に以下を重点的に抽出する（Learning Intent）
   - 意図が後工程へ伝わらなかった点（どの Intent がどこで途切れたか）
   - 認知負債になりかけた点（記録すべきだったのにされなかった判断）
   - 短期コンテキストの昇格漏れがなかったか
   - プロセスが重かった点（形骸化した記載、不要だった承認）
4. フロー中に捕捉した発見（アイデア・フォロー候補・スコープ外化した要求）をまとめてトリアージする。各件を次のいずれかに割り当てる:
   - 着手を決める → product-intent → Issue 化
   - その場で修正（数分で直せる負債）
   - `roadmap` 等に候補として保持
   - 破棄
   フロー中に個別 Issue を量産せず、ここで昇格・整理する（未検証のアイデアを一級 Issue として滞留させない）
5. 振り返り結果を GitHub Issueへコメントする
6. playbook の skill・テンプレートへの具体的な改善を提案し、人間が採用したものは playbook への PR またはIssue にする
