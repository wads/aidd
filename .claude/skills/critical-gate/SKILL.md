# Critical Gate

## いつ使うか

- P7 で人間の PR レビューへ入る前（必須ゲート）
- P2 の AC/QC 確定を人間へ求める前（軽量版）
- P5 の実装計画承認を人間へ求める前（軽量版）
- 人間レビューの負荷を下げつつ、AI 作業者への同調バイアスなしに欠陥を先に潰したいとき

## 入力

- 対象フェーズ（P2 / P5 / P7）と成果物（Issue の AC/QC 案、実装計画、PR 差分 + AC⇄テスト対応表）
- 参照する上流記録（Issue 本文、確定版 AC/QC、ADR・設計書）

## 出力

- 指摘一覧（重大度 Critical / Warning / Suggestion、**戻り先フェーズ判定つき**）→ PR または Issue コメント
- ゲート判定: 通過 / 不通過（不通過なら戻り先と差し戻し内容）
- 通過後: 人間レビューで見るべき残論点の要約

## 扱う Intent

- Verification Intent（批判的検証）/ Product・Design・Decision Intent（整合確認の入力）

## 原則

- レビュー agent は実装した文脈を引き継がない（独立性）。「否定する前提」で読む
- 指摘は必ず戻り先を判定する: 要求の欠陥 → P2、設計の欠陥 → P3/P4、実装の欠陥 → P6、表現のみ → その場修正
- Critical が残る限り通過させない。通過のために指摘を弱めない
- ゲートは人間レビューの代替ではなく前処理。通過しても最終判断は人間が行う
