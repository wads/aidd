# 実装方針テンプレート

置き場: スタックにしない計画は draft PR 説明文、スタック構成に合意した計画は Issue コメント（`workflow.md` §3・§4）。

```md
## 実装方針（P5 実装計画）

参照: {Issue 番号}、合意した設計 {リンク or なし}、ADR {リンク or なし。この Issue で作ったものに加え、`adr/INDEX.md` の同 topic で従うべき既存 ADR も挙げる}

### ステップ

| # | 内容 | 区分 | 対応 AC | 備考 |
|---|---|---|---|---|
| 1 | {再現テストを書く} | TDD | AC-1 | |
| 2 | {設定値を追加する} | DIRECT | QC-2 | 実施手順: {…} / 検証手順: {…} |
| 3 | {不変条件を確かめるテストを書く} | TDD | QC-1 | 不変条件 B1 |

### 触らない範囲
- {範囲}: {理由}
- N{n}: {Issue のやらないこと}。{理由}

### リスクと検証方針
- {リスク}: {検知・回避方法}

### 人間確認ポイント
- ステップ {n} 完了時: {確認内容}

### 机上のなぞり（feature / refactoring。計画の時点の見込み。外れること自体は停止にしないが、停止条件は今までどおり）
| # | 触るファイル | 最初に書くテスト / 検証手順 | 決めること（行き先と答え） | 未確認の前提（結果 / リスク） |
|---|---|---|---|---|
| 1 | {ファイル名} | {テスト名 / 検証手順 / 守りに使う既存のテスト} | {選択 → 行き先 (a)〜(e) と答え / なし} | {前提 → 確かめた結果 / リスクへ / なし} |

### 計画外の停止（P6 で追記。feature / refactoring）
- {n}: {理由} / 先に出せたか（AI の申告）: {はい・いいえと理由} / {リスクに書いていたものが当たった場合は「計画に書いていた」}。無ければ「0 件」

### TODO リスト（P6 で更新。最終状態を残す）
- [ ] {振る舞い}（AC-n / QC-n）

### Red の記録（P6 で追記。各サイクルの失敗行を 1 行転記）
- {サイクル}: `{失敗行}`

### Refactor の記録（P6 で追記。各サイクルの実施内容、または「不要（理由）」を 1 行転記）
- {サイクル}: {実施内容 / 不要（理由）}
```

ルール:

- DIRECT のステップは実施手順と検証手順を必ず書く（テストが無い分、検証を明文化する）
- スタック構成に合意した計画では「PR」列を追加し、各ステップの PR と base を書く:

  ```md
  | # | 内容 | 区分 | 対応 AC | PR | 備考 |
  |---|---|---|---|---|---|
  | 1 | … | TDD | AC-1 | step1（base: {既定ブランチ}） | |
  | 2 | … | TDD | AC-2 | step2（base: step1） | |
  ```
- bugfix の簡易計画はこの表を 1 段落に圧縮してよい（再現テスト → 修正 → 回帰確認）。**簡易計画は 1 PR で出す**（段落内の 3 つの作業をスタックに分けない）
- 「机上のなぞり」と「計画外の停止」の欄は、feature / refactoring の計画に書く（定義と書き方は `workflow.md` の「机上のなぞり」の節、記録の手順は `tdd-cycle/workflow.md` の「計画外の停止の記録」の節）。計画の全体で「決めること」が 1 件も無いときは「なし」と理由を、未確認の前提が 1 件も無いときは「なし」と確かめた範囲を、表の下に書く。bugfix の簡易計画には書かない
- 計画からの逸脱（スコープ変更・想定外・新しい技術判断）が生じたら停止して人間へ確認する
- 「対応 AC」列は **計画時点の暫定**。実装で可否・粒度が変わりうる。P6 実装 exit で実際のテストと突き合わせて更新する（`tdd-cycle` の「実装後の突き合わせ」を参照）。未検証の AC は `手動(P7 検証・レビュー)` / `別Issue(#n)` / `対象外` を明示し、裏付けの無い「assert 済み」を残さない
- やらないことは「触らない範囲」に `N{n}` と理由だけを書く。ステップ表には載せない（P7 で差分と照合する）
