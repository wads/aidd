# [ADR-0006] 積み替え後は判定を行わず常に再ゲートする

## ステータス

承認済み（2026-09-05）。**ADR-0004 を置き換える**（Replaces: ADR-0004）。**ADR-0007（機構を `gh stack` に委ねる）の後も有効**: これはプロセスの規則であり、機構をどちらが持つかに依存しない。ADR-0004 が置き換えた ADR-0003 論点 3（range-diff による判定）も、あわせて採用しない。

## 背景

積み替え後に「その PR の差分内容が変わったか」を機械的に判定し、変わっていなければ再ゲートを免除する、という方式を 2 度試みた。

1. ADR-0003 論点 3: `git range-diff` の判定 → **過検知**。下位が上位の変更箇所の近傍を触るだけで「変わった」と出る
2. ADR-0004: 変更行の比較 → **見逃し（fail-open）が繰り返し発見された**。当初 5 クラス（rename 先の変更・バイナリ・file mode・末尾改行・同一行の位置移動）、それを塞ぐ修正が新たに 2 クラス（別ファイルの mode 変更・空ファイルの作成）を生み、さらにバイナリの内容変更は `git diff` の出力が `Binary files … differ` のみで内容を運ばないため**原理的に塞げない**ことが判明した

見逃しはすべて「再ゲートが不要」と誤る方向、すなわちゲートを素通りさせる方向に働く。P7 の批判的レビューゲートで同じ領域の指摘が 2 巡し、修正のたびに新しい穴が見つかる状態になった。

## 検討した選択肢

### 案 1: 判定をやめ、積み替えたら常に再ゲートする（採用）

- 概要: 積み替え・base 付け替えを行った PR は、差分が変わったかによらず「critical-gate 通過済み・人間チェック済み」を失効させ、再ゲート → 再チェックを行う
- メリット: 見逃しがゼロになる。規則が単純で、判定コマンドの正しさに依存しない。ゲートの信頼性が判定ロジックの品質から切り離される
- デメリット: 下位の軽微な修正のたびに上位すべての再ゲートが走る。スタックの利点である「軽い反復」を相殺する

### 案 2: 変更行の比較を続け、見つかった穴を塞ぎ続ける（ADR-0004 の継続・棄却）

- メリット: 実質不変の PR で再ゲートを省ける
- デメリット: 2 度の修正がいずれも新しい穴を生んだ。穴の全体像が把握できておらず、「塞いだ」と書いた記述が実測で誤りだった実績がある。ゲートの信頼性を、網羅性を保証できない正規表現に預けることになる

### 案 3: バイナリ専用の追加検査などで補強（棄却）

- メリット: 見逃しを減らしつつ免除も残せる
- デメリット: 手順が複雑になり、複雑さ自体が新しい穴の温床になる（案 2 で 2 度経験した）。判定の網羅性は依然として保証できない

## 決定内容

積み替え・base 付け替えを行った PR は、差分の変化を判定せず、**常に**次を行う。

- 積み替えの**直後**に「critical-gate 通過済み」「人間チェック済み」を失効させる（ready 化済みなら `gh pr ready --undo` で draft に戻す）
- critical-gate の再実行は、**次にその PR を人間チェックへ出す直前**に行う（通常は最下段へ昇格したとき）。積み替えのたびに全上位を即座に再ゲートはしない
- 守るべき不変条件は「人間チェックに出す差分・マージする差分は、常にその時点でゲートを通っている」こと。実施時点をチェック直前に寄せてもこれは保たれる

`git range-diff` は判定には使わないが、**人間が変化を読むためのビュー**としては引き続き有用なので、記録目的での併用は妨げない。

## 設計意図

再ゲート要否はゲートの信頼性の中核であり、**誤るなら安全側（過剰にゲートする側）に倒す**。判定ロジックの網羅性を保証できない以上、免除の仕組みを持つこと自体がゲートの信頼性を毀損する。aidd の不変条件「ゲートの信頼性」を「軽さ」より優先する。

## トレードオフ

- 免除が無いため、各 PR は人間チェックへ出すたびにゲートを通る。実施時点をチェック直前に寄せることで、積み替えのたびに全上位を再ゲートする最悪ケース（段数 n に対して O(n²) 回）は避けている
- 機械的な base 付け替え（内容が変わらないことが自明なケース）でも再ゲートが必要になる
- このコストが実運用で許容できないと分かった場合は、パイロットの結果をもって免除の仕組みを再検討する（そのときは網羅性の保証方法とセットで判断する）
