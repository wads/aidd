# [ADR-0012] 画面に現れ、区別を定めたシステムの語を用語集に載せる

## ステータス

承認済み（2026-10-30 人間承認）

## 背景

ADR-0011 は、用語集に載せるのはドメインに固有の語だけとし、システムの機能・処理の名前は載せないと決めた。

利用側の remosys では、推移グラフの「選択期間」「拡大範囲」「表示範囲」を利用側の ADR で区別している。判定と描画でどちらの範囲を使うかが仕様なので、取り違えると振る舞いが変わる。これらはドメインの語ではないため、ADR-0011 の規則では用語集に載せられず、発注者・開発者・AI が同じ言葉を使うための正本が無い。

## 検討した選択肢

### 案1: 画面に現れ、区別を定めた語だけを例外として載せる（採用）

- メリット: 取り違えると仕様が変わる語に正本ができる。載せる語が絞られたままになる
- デメリット: 「ドメインに固有の語だけ」という基準が単純でなくなる

### 案2: 画面に現れる語をすべて載せる

- メリット: 基準が単純になる
- デメリット: 凡例など一般的な語まで載り、照合の手がかりとしての用語集の価値が下がる

### 案3: 載せない（ADR-0011 のまま）

- メリット: 規則を変えなくてよい
- デメリット: 定義が ADR や設計書に留まり、用語集との照合の対象にならない

## 決定内容

1. ADR-0011 決定 2 に例外を足す。**利用者の画面に現れ、似た語との区別を ADR や設計書で定めたシステムの語は、用語集に載せる**
2. それ以外のシステムの機能・処理の名前、一般的な語、環境の名前は、これまでどおり載せない

## 設計意図

用語集の価値は、AI が人間の言葉どおりに実装・出力することにある。載せる基準を「システムの語かどうか」だけで分けると、区別が仕様に効く画面の語が抜け落ちる。一方で、載せすぎると照合の手がかりにならないという ADR-0011 の理由は変わらないので、例外は「区別を定めた語」に絞る。

## トレードオフ

- 用語集に、ドメインの専門家が使わない語が少し混ざる。大きくなる場合は別のファイルに分けて、用語集の冒頭から参照する
