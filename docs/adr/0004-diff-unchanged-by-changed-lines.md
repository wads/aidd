# [ADR-0004] 積み替え後の diff 不変判定を変更行の比較で行う

## ステータス

承認済み（2026-09-05）。**ADR-0003 の論点 3（diff 不変判定）を置き換える**（Replaces: ADR-0003 論点 3）。ADR-0003 の他の論点（基盤・積み替え方式・計画の置き場・マージ方式）は有効。

## 背景

ADR-0003 論点 3 では、積み替え後に各 PR の差分内容が変わったか（＝再ゲートが必要か）を `git range-diff` の判定で決めるとした。

Issue #18 の QC-1 検証（手順書のみを渡した別セッション AI が squash 運用の repo で 3 段スタックを実運用）で、この判定が**過検知する**ことが実測された。下位ステップが上位ステップの変更箇所の近傍（±3 行）を触ると、上位 PR の追加・削除行が完全に同一でも range-diff は差分あり（`!`、場合によりコミットの対応づけ自体の失敗）と表示する。コンテキスト行が変わるためである。

現行ルール（`!` があれば内容が変わった → ゲート通過とチェック済みが失効し再ゲート必須）を literal に適用すると、実質不変の PR に対して再ゲートが繰り返し発生する。下位の軽微な修正で上位が近傍にあるだけで起きるため、頻度は低くない。

## 検討した選択肢

### 案 1: 変更行のみの機械比較を判定に使う（採用）

- 概要: `git diff` の出力から変更行（`+`/`-`）とファイル名ヘッダだけを抽出し、積み替え前後で比較する。空なら不変。`range-diff` は人間が変化を読むためのビューとして併用する
- メリット: コンテキスト行の差を無視できる。判定は機械的なまま（AI の裁量が入らない）。git と POSIX 標準ユーティリティ（`diff` / `grep`）のみで、追加ツールの導入は不要（ADR-0003 の基盤方針を維持）
- デメリット: `range-diff` ほど読みやすい出力ではないため、変化の中身を人間が見るには併用が要る

### 案 2: `!` なら常に再ゲート（ADR-0003 のまま）

- 概要: 過検知を許容し、疑わしきは再ゲートする
- メリット: 最も fail-closed。判定規則が単純
- デメリット: 下位の軽微な修正のたびに上位全体の再ゲート（独立 agent 群の実行）が走り、スタックの利点である軽い反復を相殺する

### 案 3: AI が range-diff を読んで判断する

- 概要: 「変化がコンテキスト行のみか」を AI が読み取って判定する
- メリット: 追加のコマンドが不要
- デメリット: ゲートの信頼性が AI の裁量に依存する。機械的判定という前提が崩れる

## 決定内容

積み替え前後の diff 不変判定は、変更行とファイル名ヘッダ、および rename・mode・バイナリ・末尾改行のマーカー行のみを抽出した比較で行う。

```bash
PAT='^([-+]|rename (from|to) |old mode |new mode |Binary files |\\ No newline)'
diff <(git diff {旧base}..{旧head} | grep -E "$PAT") \
     <(git diff {新base}..{新head} | grep -E "$PAT")
```

出力が空なら不変（再ゲート不要・テスト再実行のみ）、出力があれば内容が変わった（再ゲート必須）。`range-diff` は判定ではなく、人間が変化を読むためのビューとして併用する。

## 設計意図

再ゲート要否はゲートの信頼性の中核であり、判定は機械的で再現可能でなければならない（AI の裁量に委ねない）。同時に、過検知は「軽い反復」というスタック運用の目的を損なう。変更行だけを比較対象にすることで、判定の機械性を保ったままコンテキスト行由来の偽陽性を除ける。

## トレードオフ

- 意味的な変化のうち「変更行が同一なのに周囲の変化で振る舞いが変わる」ケースは、この判定では不変と出る。これは積み替え後のテスト再実行（green 確認）と最終 PR の横断確認で捕捉する前提を維持する
- **同じ行が同一ファイルの別位置へ移動しただけの変化**も、判定が位置情報を持たないため不変と出る（コンフリクト解消で起こりうる）。同上の再実行で捕捉する前提とする（2026-09-05 追記: P7 ゲートの実測指摘による）
- 変更行だけを抽出すると、rename 先の変更・file mode 変更・バイナリ差分・末尾改行の有無を取りこぼす。判定パターンにこれらのマーカー行を含めることで塞いでいる（2026-09-05 追記: 同上）
- 判定コマンドがプロセス置換を使うため bash / zsh が必要（`sh` / dash では動かない）
- 出力が読みにくいため、変化があった場合の中身の確認には `range-diff` の併用が必要になる
