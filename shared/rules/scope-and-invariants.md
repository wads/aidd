# やらないこと・不変条件の区分

Issue で「〜しない」と否定形に書ける項目を 3 つに分ける。P1（`product-intent`）と P2（`requirements`）は、分類をこのファイルで判断する。

| 区分 | 例 | Issue 本文の置き場 | 確かめる条件 | 確かめ方 |
|---|---|---|---|---|
| 範囲外 | 取り込み処理は別 Issue で作る | やらないこと `N1`… | AC にしない。N 番号のまま対応表に載せる | P7 で、差分と N を 1 件ずつ照合する |
| この Issue で決める振る舞い | 補正係数を変更すると、前の値は残らない | 作るもの・受入れ条件 | やることの AC | テスト |
| 不変条件（今の動きを変えない） | 未対応の種別のデータを置いても、取り込みは行われない | 不変条件 `B1`… | QC（refactoring は AC）。出典は `不変条件 Bn` | テスト |

- **見分け方**: 差分にコードが無いことで確かめられるなら範囲外。テストを書かないと確かめられないなら振る舞いで、新しく決めるものは 2 行目、今の動きを守るものは 3 行目
- **分類は AI が提案する**: 人間には見分け方を問わず、「範囲外 / この Issue で決める / 今の動きを変えない」の 3 択で聞く
- **N と B は全件を追う**: P2 の確定時に、N は全件を対応表の N の行に、B は全件を QC（refactoring は AC）にする。確かめる場所の無い項目は、誰にも確かめられない
- **混ざっていたら移す**: 区分の誤りに気づいたら正しい置き場へ移し、AC 確定コメントの備考で申告して、本文の訂正を Intent Delta で残す
