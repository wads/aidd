# AC⇄検証対応表（共通テンプレート）

受入れ条件（AC）・品質条件（QC）と検証の対応を追跡する唯一の表形式。P2 の確定時に骨格を作り、以後 Issue コメント・PR 説明・スナップショットのすべてで**同じ表を更新して使い回す**（場所ごとに形式を発明しない）。目的は、読み手が一枚で「Issue 本文の受入れ条件 → AC-ID → 検証の実体」を追えること。

| ID | 条件（一行要約） | 本文対応 | 検証手段 | 検証の実体 | 状態 |
|---|---|---|---|---|---|
| AC-1 | 機能が無効のときは何もせず正常終了する | 受入れ条件 1 | unit | `test_skips_when_disabled` | ✅ |
| AC-2 | 対象データを投入すると変換が実行される | 受入れ条件 1 | integration | `TestConversionEndToEnd` | ⏳ P6 |
| AC-3 | （やらないこと）無効な種別のデータは取り込まれない | やらないこと N1 | integration | `test_ignores_unsupported_type` | ✅ |
| AC-4 | （やらないこと）一覧に削除操作が追加されていない | やらないこと N2 | 差分確認 | P7 記録（PR コメント）へのリンク | ⏳ P7 |
| QC-3 | 検証環境の実データでの表示確認 | −（P2 確認ループ） | 手動 | P7 記録（Issue コメント）へのリンク | ⏳ P7 |

記入規則:

- **1 行 1 条件・要約は一行**。理由・経緯・実装の説明は書かない（それらは AC 確定コメントや設計書にある）
- **本文対応**: Issue 本文の受入れ条件番号。本文に無い派生条件は「−（出典）」と書く。やらないことの AC は `やらないこと Nn` と書き、要約の頭に `（やらないこと）` を付ける
- **検証手段**: P2 で割り当てたテストレベル（unit / integration / E2E）・検証手段タグ（CI / 手動）・`差分確認` をそのまま使う
- **検証の実体**: 実在するテスト名（クラス・関数）または手動検証記録へのリンク。**実在しないものを書かない**（実績主義。`tdd-cycle/workflow.md` の対応表規律）
- **状態**: ✅ 検証済み / ⏳ 未実施（実施予定フェーズを添える）/ ❌ 不合格（対応を添える）
- P2 確定時は「検証の実体」を空欄・状態を ⏳ とした骨格を作り、以後は**この表だけを**更新する
