2. 今回の判断

求める判断: PR #27 を main へ受け入れるか。ゲートは 2 視点で 1 回目不通過（Critical 1 件）、再ゲートで通過（Warning 7 件はすべて表現で、最終コミットで解消済み）。

すでに確定した判断（選択式の問いで人間が採用）:

  1. snapshot は Artifact で公開し、同じ Issue では 1 URL を判断ポイントごとに更新。途中版は .snapshots/ に連番で残す
  2. P4 設計は構造基準（テスト以外のコードの新設、責務分割・依存方向の変更）に当たれば必須。テンプレートに構造図・命名とパターン・技術的負債の方針を追加
  3. ゲートの設計レンズに「設計書が無い変更で構造の判断が diff に埋まっていないか」「技術的負債を増やしていないか」を追加
  4. 構造基準は規模軸ではなく「設計判断が生じたとみなす条件」として判断駆動の原則の中に置く（2026-06-12 の規模軸廃止は維持）
  5. Artifact 前提とし、Codex 等での代替は未定と明記。構造基準に当たる変更では「ADR なし」も人間が確定。基準の下限（新規ファイル 1 本でも短い設計書）はこのまま
受入れ時に見る残論点: (a) chore / bugfix では設計レンズが走らないため、構造基準に当たる chore はマージ前契約チェックで拾ってタイプ見直しを求める形にした（内容の検査はしない）。(b) Artifact は Claude Code 固有で、Codex 併用時の snapshot 公開先は未定。(c) 「設計書なし」「ADR なし」の確定は P4 の設計承認の問いにまとめる運用で、初回適用は次の feature になる。
