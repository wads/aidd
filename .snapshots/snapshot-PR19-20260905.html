外部レビュー後に確定した判断（用語: considered = 同 topic の既存 ADR を読んで無関係と判断した番号の欄 / 網羅規則 = 同 topic の若い番号の有効 ADR がすべて supersedes・amends・considered に現れるかの機械検査 / ハブ移行 = remosys-context の既存 9 本を新規約に合わせる作業 #79）:

  1. 語彙表は ADR ディレクトリの外 {records_root}/domain-terms.md（ハブは system/domain-terms.md）。README.md は人間向け説明に空ける
  2. summary（要旨一行）を必須にし INDEX.md の行に出す。同 topic を全読みする側のコンテキストを索引で絞る
  3. considered と網羅規則で「読まずに飛ばした」を機械検出する。移行時は一括記入になる負荷を受容（トレードオフに明記）
  4. 決定 3（旧 ADR の frontmatter 編集は status・逆リンク・updated のみ）は狭いまま残し、本 PR と #79 の遡及付与は今回限りの例外。規約には書かない
  5. 任意の issue 欄をテンプレートに追加

再レビュー（2026-09-09）で確定したこと: 網羅検査は「同 topic を名乗りながら先行 ADR を挙げていない」ことだけを止める（新 topic 経路と列挙経路は通る）と ADR-0008 に明記。旧 ADR 本文の status 欄の食い違いは決定 3 の帰結として受容。INDEX.md の手書きは不可（python3 のある環境で生成）。ハブの実態は system 10 本 + services 1 本で、移行に番号衝突の解消が加わる（#79 に反映）。

  2. INDEX.md 先頭の再生成手順はプレースホルダ（実パス展開は環境依存で --check が割れる）

4. 設計と構造

4-1. 設計方針 🟡

  • 手書きは各 ADR と語彙表だけ。索引は常に再生成できる従属物にして腐らせない
  • 語彙表と索引を別ファイルにするのは、生成時の照合相手を作るため（単一ファイルでは語彙表に無い topic を検出できない）
  • 照合は fail-closed。「証拠の不在」（README 無し）と「OS エラー」を区別し、後者は error にする（ゲート 3・4 回目で閉じた故障クラス）
  • 「引く」「衝突に気づく」「失効を知る」を人間の記憶からスクリプトと frontmatter に移す
